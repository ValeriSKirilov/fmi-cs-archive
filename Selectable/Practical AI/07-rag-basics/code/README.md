# Упражнение 7: код

Практическа част към Лекция 7. Сглобяваме **базов RAG** от частите, които вече
познаваме: embeddings (Тема 5), векторна база (Тема 6) и генеративен модел
(Теми 1 и 2). Този pipeline надграждаме в Тема 8.

## Принцип на курса: RAG на ръка

> Сглобяваме стъпките сами: при зареждането LOAD, SPLIT, EMBED, STORE, а при
> всеки въпрос EMBED, RETRIEVE, AUGMENT, GENERATE. Библиотеки като LangChain
> правят същото зад по-удобен интерфейс, но първо
> трябва да видим какво точно крият.

Всичко върви **офлайн, без ключ**: pgvector през Docker и локален Ollama за
embeddings и генериране. Облачен модел за генериране се включва с
`GEN_PROVIDER` в `.env`.

## Задачи

1. **Подготовка на данните.** Попълнете `split_text` в `chunk.py`:
   деление на части с припокриване. После пуснете `01_ingest.py` и пробвайте
   различни размери на частите.
2. **Отговор с източници.** Попълнете в `rag.py` инструкцията `GROUNDED_SYSTEM`
   („само от контекста“) и `build_prompt` (номериран контекст).
   Пуснете `02_answer.py`: два въпроса от корпуса и два извън него. После
   същото с `--no-grounding`, за да видите как моделът си измисля без
   инструкцията.
3. **Къде е грешката?** Без нов код. `03_diagnose.py` показва намерените части
   и отговора за няколко въпроса, включително с точен код (`E-1042`). Решете
   дали грешката е в търсенето или в генерирането. Това води към Тема 8.

**Бонуси, без нов код:** `02_answer.py --stream` (стрийминг, Тема 4) и
`02_answer.py --json` (цитатите като структуриран изход, Тема 3).

## Файлове

```
code/
  01_ingest.py  02_answer.py  03_diagnose.py   скриптовете на задачите (готови)
  store.py      generate.py                    pgvector и моделът (готови)
  starter/      chunk.py  rag.py               вашият код, с TODO
  solutions/    chunk.py  rag.py               решенията, за сверка
  corpus/                                      малка вътрешна база знания (.md)
```

- `chunk.py`: LOAD и SPLIT (задача 1).
- `rag.py`: EMBED, RETRIEVE и AUGMENT (задача 2).

Скриптовете ползват вашия код от `starter/`. С `--solutions` ползват готовите
решения, например за да сравните поведението.

## Подготовка

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env

docker compose up -d          # pgvector, както в Тема 6
ollama pull bge-m3            # embeddings, многоезичен (Тема 5)
```

## Стартиране

```bash
python 01_ingest.py                      # индексиране, веднъж
python 01_ingest.py --chunk-size 200     # експеримент с размера
python 02_answer.py
python 02_answer.py --no-grounding
python 02_answer.py 'Колко дни е годишният отпуск?' --stream
python 03_diagnose.py
python 02_answer.py --solutions          # същото, с готовите решения
```

## Бележки

- **Един и същ embedding модел** при зареждането и при въпроса. Иначе векторите
  са в различни пространства и резултатите нямат смисъл.
- **Инструкцията „само от контекста“** е ключова: без нея моделът отговаря от
  собствената си памет и си измисля (задача 2б).
- **Зареждането е еднократно:** `01_ingest.py` не се пуска при всеки въпрос, а
  само когато документите или размерът на частите се променят.
- **Смяна на embedding модела:** сменете и `vector(1024)` в `db/init.sql`,
  после `docker compose down -v && docker compose up -d`.
