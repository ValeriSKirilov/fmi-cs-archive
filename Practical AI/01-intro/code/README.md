# Упражнение 1 — код

Практическа част към Лекция 1. Едно и също извикване на LLM, минато през
три нива на абстракция (суров HTTP → официален SDK → provider-agnostic
адаптер), плюс локален модел през Ollama и мини-разговор, който показва как
се управлява контекстът.

Общо пишете около **30 реда код** в четири функции. Всичко останало е
готово — целта е да разберете какво се случва, а не да преписвате.

## Преди упражнението (направете го вкъщи)

```bash
# 1. Виртуална среда (от папката lectures/01-intro-apis/code)
python3 -m venv .venv && source .venv/bin/activate
#    Windows:  .venv\Scripts\activate

# 2. Зависимости
pip install -r requirements.txt

# 3. API ключ
cp .env.example .env
#    редактирайте .env и сложете ключа си (НИКОГА не го commit-вайте)

# 4. Два локални модела — ~3.8 GB общо, направете го предварително!
#    инсталация: https://ollama.com
ollama pull llama3.2:1b
ollama pull hf.co/INSAIT-Institute/BgGPT-Gemma-3-4B-IT-GGUF:Q4_K_M
ollama cp   hf.co/INSAIT-Institute/BgGPT-Gemma-3-4B-IT-GGUF:Q4_K_M bggpt:4b
```

**Защо два.** `llama3.2:1b` е общ модел с 1B параметъра — бърз и малък, но на
български пише безсмислици. `bggpt:4b` е **BgGPT** на INSAIT (Gemma 3, 4B),
допълнително обучен за български — по-бавен, но свързан. Задача 2 пуска един и
същ въпрос през двата, за да се види, че изводът не е „локалното е по-лошо",
а че **размерът и езиковата адаптация решават**.

Третата команда е само преименуване: `hf.co/...` е адресът, от който Ollama
тегли файла, а `bggpt:4b` е краткото име, с което работи кодът.

BgGPT се тегли от **официалното** репо на INSAIT в Hugging Face. В каталога на
Ollama има и потребителски копия — те може да носят променен шаблон или
параметри и да изчезнат по всяко време.

За по-силна машина: `INSAIT-Institute/BgGPT-Gemma-3-12B-IT-GGUF:Q4_K_M`
(7.3 GB) е забележимо по-добър от 4B варианта.

Накрая проверете всичко с:

```bash
python check_setup.py
```

Скриптът проверява версията на Python, пакетите, `.env`, ключа, една реална
заявка до Anthropic и наличието на локалния модел — и при всеки провал казва
точно коя команда да изпълните. Ако нещо не е наред, оправете го **преди**
упражнението.

редът с usage. Прегледайте го — за да знаете какво ви е спестено.

## API ключ

Обичайният случай е Console API ключ от
<https://console.anthropic.com> (започва със `sk-ant-api...`), който се
изпраща в header-а `x-api-key`.

Алтернатива е OAuth токен от subscription идентификация (`sk-ant-oat...`),
който върви като `Authorization: Bearer`. Задава се в `ANTHROPIC_AUTH_TOKEN`
и е резервен вариант — ако са зададени и двете, печели `ANTHROPIC_API_KEY`.
Тези токени са краткотрайни и изтичат. SDK-то избира правилния header само;
в упражнението логиката е скрита в `common.py`.
